# A-000-99 다음 실행 계획

A-시리즈(A-000~A-900)는 확정된 정의와 측정값만 적는다. 문서 밖으로 뺀 후속 작업은 이 문서에 모은다. 새 할 일이 생기면 A 문서가 아니라 여기에 적는다.

## 실행 순서

```
1단계 A-시리즈 확정 → 2단계 baseline 후속 → 3단계 채점 방식 변경 → 4단계 Langfuse 기록 → 이후 main 변경마다 전체 재측정
```

앞 단계가 끝나야 다음 단계의 숫자가 의미를 갖는다. 3단계는 채점 방식이 바뀌므로 새 기준선을 만든다(`A-000-00` §3).

## 이후 — main 변경마다 전체 재측정

main이 바뀔 때마다 질의·민원·색인 지표 전부를 다시 재서 `A-100-01`·`A-200-01`에 열로 누적한다. 운영은 새 배포가 나갈 때마다 직전 배포 기간을 집계해 `A-300-01`에 누적한다(`A-000-00` §4, `A-300-00` §0).

**미달 지표 조치** — "2회 연속 미달에 발동" 규칙에 따라 baseline이 1회차, 다음 main 변경 측정이 2회차다. 2회차에도 미달이면 각 지표의 "미달 시 조치"를 실행한다. R1·G1·G4·M8은 1건에 즉시 조치한다.

| 지표 | baseline | 2회 연속 미달 시 조치 |
| --- | --- | --- |
| R2·R3·R4 | 0.822 / 0.680 / 0.822 | `SCORE_THRESHOLD` 0.50→0.45 후 T1 재실행(한 회차에 한 단계) |
| M1 | 0.382 | `complaint/prompts.py` 추출 예시 보강 |
| M5 | 0.783 | VLM 요약 프롬프트 조정 |

## 기록이 없는 것

| 항목 | 내용 |
| --- | --- |
| 문항 구성의 처음 의도 | 235문항의 135/100 비율, 확장 15·20·12·20개, 사진 2×2 각 30장, T2 표본 60:40을 정한 당시 이유는 기록이 없다. `A-000-01`은 데이터에서 확인되는 구성 규칙만 적었다. |
| 목표값의 근거 | R4 ≥0.85처럼 목표 숫자를 고른 근거는 일부 지표에만 있다(`A-100-00` "근거" 칸). 나머지는 측정이 쌓인 뒤 다시 정한다. |

## 로그 관측 개선

지표 집계에는 영향이 없고 S2·S6만 관련된다.

| 항목 | 내용 |
| --- | --- |
| `httpx2` INFO 누출 | `observability.py`의 억제 목록에 `"httpx2"`를 추가한다. openai SDK가 `httpx2` 로거를 쓴다. |
| RapidOCR 색코드 잔존 | `setLevel`이 아니라 `addFilter`로 막는다. RapidOCR이 엔진 생성 때 로그 레벨을 덮는다. |
| embedding 내부 관측(S6) | embedding 서비스에 `queue_ms`·`infer_ms` 구조화 로그를 추가한다. 지금은 대기와 추론 시간을 나눠 볼 수 없다. |
