# A-000-00 문서 지도 · 실행법 · 버전 정의

## 읽는 순서와 용어

세 가지 평가가 있다. **질의**는 건물 문서에 근거해 답하는지, **민원**은 접수에 필요한 정보를 받아내는지, **운영**은 서비스가 느려지거나 실패하지 않는지를 본다(운영은 답의 품질을 판정하지 않는다).

처음 읽는다면 이 순서가 자연스럽다.

1. 이 문서 — 문서 지도, 버전, 재측정 범위
2. `A-000-01` — 시험지(문항 462개 + 색인 문서 51건), 지표별 사용 문항, 실행 방법
3. `A-100-00`·`A-200-00`·`A-300-00` — 질의·민원·운영 지표의 정의와 근거
4. `A-100-01`·`A-200-01`·`A-300-01` — 버전별 점수 (`A-100-02`는 구 평가 코드 시절의 참고 기록)
5. `A-900-00` — LLM Judge 방식

| 용어 | 뜻 |
| --- | --- |
| 색인 | 건물 문서를 조각(청크)으로 잘라 검색 DB(Qdrant)에 넣는 일 |
| 청크 | 색인할 때 문서를 400자 안팎으로 자른 조각 |
| 게이트 | 검색 점수가 임계값(`SCORE_THRESHOLD`, 0.5) 아래면 답을 쓰기 전에 "근거 없음"으로 거르는 1차 관문 |
| 골드셋 | 정답이 붙은 문항 모음(`goldset.jsonl`) |
| 평가 스크립트 | 문항을 모델에 넣고 답을 받아 정답과 비교해 점수까지 내는 파이썬 파일(`evals/`). 이름은 아래와 같다 |
| 검색 채점(T1)·답변 채점(T2)·길 고르기 채점(T3) | 질의 평가 스크립트 `run_t1.py`(R1~R7)·`run_t2.py`(G1·G2·G5·G6)·`run_g7.py`(G7, T2 결과로 채점)·`run_t3.py`(C1) |
| 확장 답변 채점·확장 길 고르기 채점·색인 채점 | `run_ext_answer.py`(G3·G4·C3)·`run_ext_route.py`(C2)·`run_k1.py`(K1) |
| 민원 글 채점·민원 사진 채점 | `run_m1.py`(M1·M2·M7·M8·M9)·`run_m2.py`(M4·M5·M6) |
| 기준선(baseline) | 첫 측정값. 이후 버전은 이 열과 비교한다 |
| 임베딩 | 문장을 숫자 벡터로 바꾸는 일. 검색 모델은 `bge-m3`(dense·sparse 두 벡터) |
| RRF·DBSF | dense·sparse 두 검색 결과를 하나로 합치는 방식. 지금은 순위 기반인 RRF를 쓰고, DBSF는 점수 기반 대안이다 |
| `doc_id` | 문서 하나의 식별자(예: `b001-rule-001-생활수칙`). 검색 결과에 정답 문서가 있는지 비교할 때 쓴다 |
| 감사 대표 20문항 | T2 표본 100문항에 항상 들어가는 20문항(`evals/query/score_t2.py`의 `TABLE_B`). judge 사람 감사 대상이고, 사람 판정은 `A-100-03`에 적는다 |

## 2. 벤치마크 위치 (시험지)

경로는 `KTB4-19th-AI` 기준. 

벤치마크 파일 목록·연결 정보·실행 순서·자주 걸리는 함정은 `A-000-01-위치와실행방법.md`에 기술되어있다.

운영(I·Q·S)은 벤치마크가 없다 — 실사용 트래픽의 CloudWatch 로그가 시험지를 대신한다(`A-300-00-운영-사양.md` 참조).

## 3. 버전 정의

- 버전은 **공식 배포 단위**다. v1의 공식 첫 배포는 2026-10-02(`aa18cc0`)이고, v2는 팀이 공식 배포로 정한 시점에 올린다.
- `v1 #N`은 v1 이후 N번째 운영 배포다. 개선 사항과 다음 버전에 들어갈 기능을 먼저 반영한 배포도 공식 버전이 바뀌기 전까지는 `#N`으로 센다.

| 열 이름    | SHA       | 운영 배포 완료(KST)       | 내용                                                        |
| ------- | --------- | ---------------- | --------------------------------------------------------- |
| `v1 #1` | `aa18cc0` | 2026-10-02 14:46 | v1 공식 첫 배포, baseline                                      |
| `v1 #2` | `ca206a7` | 2026-10-07 21:39 | 릴리스 #93 — 민원 노드 리팩토링(#90), LLM 토큰 캐시 기록(#92)              |
| `v1 #3` | `e0f3f00` | 2026-10-10 00:17 | 릴리스 #99 — 이미지 분석을 의도 분류·지식 검색에 통합(#97), 민원 대표 이미지 추천(#98) |

## 4. 언제 재측정하나

| 대상 | 시점 | 범위 |
| --- | --- | --- |
| 질의·민원·색인(K1) | **main이 바뀔 때마다** | 로컬 벤치마크 지표 전부(M3 제외). 바뀐 부분만 골라 재지 않는다 — 범위를 고르는 판단에서 누락이 생기기 때문이다 |
| 운영(I·Q·S)과 M3 | **새 배포가 나갈 때마다 직전 배포의 운영 기간을 집계**하고, 매일은 알람으로 점검한다 | CloudWatch 로그에서 집계한다. 방법은 `A-300-00` §0 |

측정마다 열 이름(버전·회차)과 함께 SHA·측정일을 적는다(§3·§5). 실행은 **로컬 수동**이다.

<details class="orca-details">
<summary>CI로 돌리지 않는 이유</summary>

- CI 실행 환경(GitHub Actions)은 매번 새로 뜨는 1회용 VM이라, Qdrant·임베딩을 매 실행마다 콜드스타트부터 다시 띄워야 한다.
- 현재 `KTB4-19th-AI`의 `ai-ci.yml`은 pytest만 돌리고 평가 스크립트는 부르지 않는다. 여기에 eval을 얹으면 경로 필터가 `ai/**` 전체를 한 덩어리로 보기 때문에, 검색과 무관한 변경(예: 민원 모듈의 오타 수정)에도 지표 전체가 돌게 된다.
- LLM 호출이 temperature 고정 없이 비결정적이다. 자동으로 자주 돌릴수록 신호보다 잡음이 늘어난다.
- 운영 EC2는 `ai-cd.yml`(트리거 `workflow_dispatch`, 수동)로만 배포된다 — `main` 머지가 운영 서비스를 바꾸지 않으므로, eval을 CI에 얹어도 "배포와 측정이 자동으로 같이 간다"는 이득 자체가 없다.

## 5. 공통 실행 기록

각 회차마다 아래 메타데이터를 남긴다. 실제 측정값과 `[추정]` 표시가 붙은 소요시간을 섞지 않는다.

| 필드                                      | 내용                                              |
| --------------------------------------- | ----------------------------------------------- |
| `run_id`                                | 회차 식별값                                          |
| `started_at`·`finished_at`·`elapsed_ms` | 실측 시작·종료·경과                                     |
| `git_sha`                               | 실행한 코드 SHA                                      |
| 모델                                      | 글·검색·사진·judge 모델 이름                             |
| 표본                                      | 회차, 문항 수, 성공·실패 수                               |
| 출력 경로                                   | `--out` JSON 등                                  |
| 토큰 출처                                   | Langfuse generation의 `usage_details`; 없으면 `미기록` |

- 평가 스크립트는 토큰·경과시간을 표준 출력에 자동으로 찍지 않는다 — 이 값들은 사람이 직접 기록해야 한다. 
- 측정하지 않은 값은 추정하거나 기존 버전 값으로 덮어쓰지 않고 `—`로 둔다. 
- 운영 로그의 응답시간·토큰은 여기서 중복 집계하지 않는다 — `A-300-00`·`A-300-01`의 Q1·Q13이 담당한다.
