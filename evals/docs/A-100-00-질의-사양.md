# A-100-00 질의 평가 사양

`intent_route=knowledge` 경로의 정의서. "코드로 채점"되는 부분과 "LLM Judge로 채점"되는 부분이 나눠져있다.

## 1. 여섯 단계와 지표 (질의 17개 + 색인 1개)

```
intent → encode → gate → hybrid → context → generate
```

`encode`에는 지표가 없다 — 색인과 같은 모델(`bge-m3`)을 써서 품질 문제가 안 생긴다.

**K1 하나는 이 여섯 단계 밖이다.** 질의를 테스트 하기 전, 미리 문서를 색인할 원본 51건이 Qdrant에 들어갈 때(download→parse→mask→clean→chunk→embed→upsert) md 원문과 청크가 같은 뜻인지를 본다. 파싱으로 깨진 글자도 여기서 잡힌다. R1~R7이 "검색이 그 청크를 찾았는지"를 본다면, K1은 "그 청크 내용 자체가 맞는지"를 본다. §2-1에 따로 둔다.

## 6. 측정 해상도 — 점수는 얼마나 흔들리나

아래 범위는 각 문항을 독립적인 무작위 표본으로 본다는 가정 아래, baseline 비율의 표본 오차를 설명한다. 이 평가는 고정된 시험 문항 묶음을 전부 사용하므로 이 범위를 버전 간 개선·악화 판정 기준으로 쓰지 않는다.

동전을 10번 던져 앞면이 6번 나왔다고 "앞면 확률 60%짜리 동전"이라고 하지 않는다. 다시 던지면 4번이 나올 수도 있다.  
평가도 같다. 135문항으로 잰 0.822는 "이번에 나온 값"이고, 다시 재면 그 근처 어딘가로 바뀐다. 문항이 적을수록 더 크게 흔들린다.  
모델 답변이 실행마다 달라질 수 있는 변동도 이 신뢰구간과는 별개다. 버전 간 비교는 같은 문항의 결과를 짝지어 차이를 보고, 모델의 실행 변동을 말하려면 같은 버전을 여러 번 실행한 자료가 필요하다. 이 문서의 신뢰구간 표는 표본 오차를 설명하는 참고값이며, 그 자체로 개선·악화를 판정하지 않는다.

### 여기서 나온 규칙 (§7)

1. **합격선은 5%p 단위로만 둔다.** 흔들림보다 촘촘한 선(예: 0.82 vs 0.83)으로 판정하면 운을 실력으로 착각한다.
2. **드문 사고는 비율이 아니라 건수로 센다.** "환각률 2% 이하" 같은 비율은 이 문항 수로 판정할 수 없다 — 0건으로 "2% 이하"를 말하려면 150문항, 2% 근처를 ±1%p로 구분하려면 약 750문항이 필요하다. 그래서 R1(격리)·G1(환각)·G4(인젝션)는 "0건"을 목표로 둔다.
3. **한 번 미달로는 조치하지 않고 2회 연속 미달일 때 조치한다.** 한 번은 운일 수 있다. 단, 건수 지표(R1·G1·G4)는 1건이 곧 사고라 바로 조치한다.

### 계산 근거

흔들림 폭(95% 신뢰구간)은 `1.96 × √(p(1−p)/n)`으로 구한다. `p`는 점수, `n`은 문항 수다. 아래 표는 `p`를 가정했을 때의 폭과, 그 폭에서 구분할 수 있는 최소 차이다. 문항이 15개처럼 아주 적으면 이 공식도 대략적인 값만 준다.

예를 들어 `p=0.82`, `n=135`이면 오차폭은 약 ±6.5%p다. 같은 비율에서 오차폭을 약 ±2%p로 좁히려면 계산상 약 1,418문항이 필요하므로, 대략 1,500문항 규모가 된다. 이는 모집단 비율 추정용 표본 수 예시이며, 고정 벤치마크의 버전 간 판정 기준은 아니다.

| 측정 집단 | n | p 가정 | 95% 신뢰구간 | 판정 가능 최소 차이 |
| --- | --- | --- | --- | --- |
| 답있음 전체 | 135 | 0.95 | ±3.7%p | 5%p |
| 답있음 전체 | 135 | 0.85 | ±6.0%p | 10%p |
| 답있음 전체 | 135 | 0.70 | ±7.7%p | 10%p |
| 답있음 건물고유 | 97 | 0.95 | ±4.3%p | 5%p |
| 답없음 | 100 | 0.80 | ±7.8%p | 10%p |
| 전체 | 235 | 0.95 | ±2.8%p | 5%p |
| C1 전체(235+47) | 282 | 0.95 | ±2.5%p | 5%p |
| G1·G5 답을 쓴 문항(baseline 54건) | 54 | 0.95 | ±5.8%p | 10%p |
| T2 표본 | 100 | 0.85 | ±7.0%p | 10%p |

**0건이 보장하는 것 (rule of three)** — n번 시도해 0건이 나왔을 때, 실제 발생률의 95% 상한은 약 3/n이다.

| 표본 | 0건 관측 시 실제 발생률의 95% 상한 |
| --- | --- |
| n=282 | 1.1% |
| n=235 | 1.3% |
| n=135 | 2.2% |
| n=100 | 3.0% |
| n=97 | 3.1% |
| n=54 | 5.6% |
| n=20 | 15.0% |
| n=12 | 25.0% |

## 7. 판정 규칙

| 규칙 | 내용 |
| --- | --- |
| **5%p 격자** | 임계값은 5%p 단위에만 둔다 — 신뢰구간이 3.7~7.8%p인데 그보다 촘촘하면 잡음을 조치로 바꾼다 |
| **비율→건수 전환** | 목표값이 신뢰구간보다 작으면 비율을 버리고 건수로 판정한다 — R1·G1·G4가 해당 |
| **2회 연속 미달에 발동** | 1회 미달은 기록만 한다. **예외** — R1 격리 위반, G1 환각, G4 인젝션 돌파는 1건에 즉시 |
| **한 회차에 파라미터 하나** | `SCORE_THRESHOLD`와 `PREFETCH_LIMIT`을 같이 바꾸지 않는다 — 두 개를 같이 바꾸면 무엇이 효과였는지 알 수 없다 |
| **판정자를 먼저 검증한다** | LLM judge 지표는 judge와 사람이 같은 답변·근거·판정 기준으로 독립 채점한 표본의 일치율을 본다. 일치율이 0.9 미만이면 판정 프롬프트를 고친다(G2는 코드 집계라 해당 없음). 기존 품질 의견을 judge 기준으로 바꾼 값은 정식 일치율로 보지 않는다(`A-100-03`, `A-900-00`) |

## 8. 지표 간 의존관계와 판정 순서

```
검색·답변: R1 격리 → R2 게이트 → R4~R7 검색 → G1~G7 답변
라우팅만: C1 knowledge 판별 · C2 complaint/clarify 판별
검색 결과를 쓰는 후속 대화: C3
```

- **R1 실패 시** — 다른 건물 청크가 섞이면 검색·답변 결과를 신뢰할 수 없다. 지표별 수치와 별도로 격리 실패를 기록한다. C1·C2는 검색 없이 경로만 보는 별도 판정이다.
- **R2 실패 시** — R4는 게이트에서 막힌 문항도 실패로 세는 전체 파이프라인 값이므로 그대로 읽는다. R5~R7은 게이트 통과 문항만 본 검색 품질이고, G1·G5~G7은 실제 답을 쓴 문항만 본다. G2는 답할 수 있는 질문을 회피했는지 별도로 본다. 이 지표들의 부분 모집단 값만으로 전체 질의 기능이 합격했다고 하지 않는다. C1·C2의 경로 판정은 별도로 읽는다.
- **R5 실패 시** — 검색된 근거의 관련성이 부족할 수 있으므로, 그 근거를 쓴 답변·후속 답변(C3) 결과는 검색 결과와 함께 해석한다.
