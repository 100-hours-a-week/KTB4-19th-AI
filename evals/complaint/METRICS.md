# 민원 파트 AI 평가 지표

> 현재 실행 가능한 지표와 seed 정답셋 범위는 [README.md](README.md)를 따른다. 아래 게이트 수치는 실측 전 제안값이며 현재 baseline으로 사용하지 않는다.

## 현재 평가 계약 (2026-09-29)

아래 표를 **이번 평가의 지표 정의**로 사용한다. 뒤의 상세 설계에 있는 수치 게이트와 미구현 지표는 향후 후보이며 현재 합격 기준이 아니다. 평가셋은 합성 seed이므로 현재 점수로 출시·모델 교체를 승인하지 않는다. 합격선은 사람 검수한 실제 사례의 최초 baseline과 오답 비용을 확인한 뒤 정한다. `baseline.py`의 0.03은 같은 셋에서의 회귀 허용폭이지 품질 합격선이 아니다.

### 태스크별 품질 판단 요약

| 태스크 | 품질 판단 지표 | 함께 확인할 실패 |
| --- | --- | --- |
| `issue_type` 분류 | 현재 턴 원시 예측의 **11클래스 macro-F1** | 급수·배수·누수 간 오분류, 근거 없는 유형 선택(`null` 오채움), 클래스별 사례 수 |
| `complaint_draft` 추출 | **접수 가능한 최종 초안의 비율**: 위치·유형·날짜가 맞고 증상이 필요한 사실을 담되 없는 사실을 추가하지 않은 대화 / 평가 대화 | 현재 턴에 없는 값 재추출, 명시적 정정 실패, 누락 정보 질문 실패 |
| 민원 대화 운영 | **실제 후속 질문의 슬롯 정확도**, 중복 질문률, 완료 턴 정확도 | 이미 받은 정보 재질문, 한 번에 여러 정보 요구, 사진만으로 증상 확정 |
| VLM 캡셔닝 | 사진의 **필수 사실 재현율**과 **근거 없는 주장 사례율** | 정상 사진을 고장으로 단정, 보이지 않는 원인 추측 |
| VLM OCR | **핵심 오류코드·수치의 정밀도·재현율**과 **전체 CER** | 글자 없는 사진의 OCR 오검출, 흐림·반사 조건별 오류 |
| 의도 라우팅 | 분류기 호출 사례의 **route macro-F1**, 민원↔지식 오분류율 | 수집 중 경로 이탈, 짧은 후속 발화의 오분류 |

분류의 원시 예측은 병합 후 `other` 보정값과 분리한다. 추출의 최종 초안 품질과 캡션의 근거 없는 주장은 사람 검수 정답이 있어야 판단할 수 있다. OCR 핵심 토큰은 `ocr_text`에서만 채점한다. 아래 세부 표는 계산식과 현재 구현 범위를 명시한다.

### 공통 집계 규칙

- 입력 단위와 분모를 점수와 함께 남긴다. 분모가 0이면 0점으로 대체하지 않고 `null`로 보고한다. 케이스 누락·모델 오류는 품질 점수에서 제외하지 않고 **실행 실패**로 별도 기록한다.
- 턴 추출과 최종 초안을 분리한다. 전자는 모델의 `delta`, 후자는 병합·`other` 보정 뒤의 `draft`를 본다. `other` 자동 보정값을 원시 분류 정답으로 취급하지 않는다.
- 평균값과 함께 클래스·조건별 사례 수와 오답 목록을 본다. 합성 사례와 추후 확보할 실제 holdout은 별도 집계한다. 같은 민원이나 사진의 변형은 서로 다른 분할에 넣지 않는다.
- 자유 문장에 대한 단어 포함 검사는 의미·부정을 판정하지 못한다. `symptom_keyword_recall`, `required_fact_recall`, `forbidden_phrase_rate`는 진단용이며 환각·충실성의 합격 지표가 아니다.

### 1. `issue_type` 분류

정답 단위는 현재 발화의 `expected.delta.issue_type`이다. 10개 유형과 `null`을 **11개 라벨**로 집계한다. 정정 발화는 현재 발화의 새 유형을 정답으로, 정보 없는 발화는 `null`로 둔다.

| 지표 | 정의와 분모 | 용도 | 현 상태 |
| --- | --- | --- | --- |
| 원시 macro-F1 | 라벨별 `2TP/(2TP+FP+FN)`의 평균. 모든 11개 라벨을 고정 포함 | 핵심 품질 | 구현됨 |
| 물 관련 구분 정확도 | gold가 `water_supply`·`drain`·`leak`인 턴 중 **정확한 유형**을 낸 턴 / 해당 턴. 세 유형 사이의 오분류도 오답 | 중요한 혼동 감시 | `water_type_accuracy` 구현 |
| `null` 오채움률 | gold가 `null`인데 원시 예측이 유형을 채운 턴 / gold `null` 턴 | 근거 없는 분류 감시 | 구현됨 |
| 최종 유형 정확도 | 병합·보정 뒤 `draft.issue_type` 일치 턴 / 전체 턴 | 제품 결과 진단 | 구현됨. 원시 분류 점수와 합치지 않음 |
| 클래스별 P/R/F1·혼동표 | 각 라벨의 TP/FP/FN과 오분류 방향, 사례 수 | 실패 분석 | 클래스별 P/R/F1·사례 수 구현. 혼동표는 미구현 |

현재 `score.py`의 `classification.macro_f1`, `null_overfill_rate`, `final_type_accuracy`가 즉시 계산된다. 실제 민원 표현에서 물 관련 경계와 희소 유형의 정답 검수를 마친 뒤 주지표 합격선을 정한다.

### 2. `complaint_draft` 추출

정답 단위는 4개 슬롯의 **이번 턴 `delta`**와 병합 뒤 `draft`다. `location`은 공백과 정해진 동의어만 정규화하고, `occurred_at`은 날짜 부분을 비교한다. `symptom`은 자유 문장이므로 문자열 완전 일치만으로 품질을 판단하지 않는다.

| 지표 | 정의와 분모 | 용도 | 현 상태 |
| --- | --- | --- | --- |
| 턴 `delta` 전부 일치율 | 4개 슬롯이 모두 정답인 턴 / 전체 턴 | 엄격한 회귀 진단 | `extraction.delta_exact` 구현. 증상 바꿔쓰기도 오답 |
| 슬롯별 정확도 | 각 슬롯의 정규화 일치 턴 / 전체 턴. 비어 있는 정답도 포함 | 오류 위치 파악 | `extraction.slot_accuracy` 구현 |
| 기존 값 재추출률 | `origin=history`인 슬롯을 현재 `delta`에 다시 낸 수 / history 슬롯 수 | 증분 추출 계약의 핵심 | `extraction.history_reextraction_rate` 구현 |
| 비어 있는 슬롯 오채움률 | 정답 `delta`가 비어 있는 location·symptom·date에 값을 낸 수 / 해당 빈 슬롯 수 | 근거 없는 추출 감시 | `extraction.over_extraction_rate` 구현 |
| 최종 구조 정확도 | 유형·위치·날짜 값과 증상 **존재 여부**가 모두 맞는 턴 / 전체 턴 | 누적 초안의 구조 회귀 | `extraction.final_structured_accuracy` 구현. 증상 내용 정확도 아님 |
| 증상 사실 충실성 | 원문·확인된 사진 관찰에 없는 사실을 넣지 않은 증상 수 / 사람이 검토한 증상 수 | 사용자 노출 품질 | 사람 라벨·판정 기준 필요 |
| 증상 필수 사실 재현율 | 정답의 명시 사실 중 출력에 보존된 사실 수 / 정답 명시 사실 수 | 접수 정보 보존 | 사람 라벨 필요. 현재 키워드 재현율은 진단용 |
| 최종 대화 성공률 | 이전 **모델** 초안을 이어 넣어 마지막에 필요한 정보와 증상이 정확한 대화 수 / 전체 대화 수 | 실제 누적 오류 감시 | 미구현. 현재 `teacher_forced_final_exact`는 정답 초안 입력·문자열 일치 진단 |

수집 상태는 별도 `dialogue` 지표로 보조 점검한다. 현재 구현된 `missing_fields_accuracy`, `state_accuracy`, `completion_turn_accuracy`는 구조·정답 문맥의 완료 시점을 본다. 답변이 실제로 한 가지 누락 정보만 자연스럽게 묻는지는 사람 검토 또는 검증된 판정기가 필요하다. 위치 거절에만 `모름`을 허용하고 증상의 `모름`·플레이스홀더는 오류로 라벨링한다.

### 3. VLM 캡셔닝·OCR

캡션(`summary`)과 OCR(`ocr_text`)을 따로 채점한다. 사진 한 장의 정답에는 확인 가능한 사실, 이상 여부, 핵심 글자, 읽을 수 없는 글자, 근거 없이 단정하면 안 되는 내용을 기록한다. **보이지 않는 고장 원인은 정답 사실이 아니다.** 현재 120장은 검수 전 후보이며 VLM 점수에 포함하지 않는다.

새 이미지 골든 셋을 만들 때는 기존 seed JSONL과 별도로 다음 필드를 먼저 라벨링한다. `reported_issue_type`은 신고·시나리오의 분류이고 `visible_anomaly`는 **사진만 보고** 확인한 상태다. 흐린 사진이나 정지 사진으로 알 수 없는 소음·급수·난방 문제는 실제 신고가 비정상이어도 `visible_anomaly="unknown"`이 될 수 있다.

| 필드 | 라벨링 규칙 |
| --- | --- |
| `id`, `image_path`, `image_sha256`, `split`, `source_type` | 이미지 식별·중복·개발/최종 셋 분리. 생성 이미지는 `synthetic`, 별도 확보 사진은 출처에 맞게 기록 |
| `reported_issue_type`, `visible_anomaly` | 신고 유형과 사진에서 보이는 이상(`true`/`false`/`unknown`)을 분리 |
| `visible_facts` | ID와 짧은 문장으로 보이는 필수 사실만 기록. 진단명이나 원인 추정은 제외 |
| `gold_ocr`, `key_tokens`, `illegible_regions` | 실제 읽히는 문자 전체, 중요한 코드·수치, 흐림·가림으로 판독할 수 없는 영역. 글자가 없으면 `gold_ocr=null` |
| `capture_conditions`, `review_status` | 흐림·반사·어두움·작은 글자 등 조건과 독립 검수 여부·불일치 해결 상태 |

정상/비정상 × OCR/무문자 네 칸의 **파일 수**와 최종 판정 가능한 **라벨 수**를 따로 센다. 생성 프롬프트에 지정한 글자와 실제 결과가 다르면 프롬프트 문구가 아닌 이미지에서 읽히는 글자를 전사한다. 판독 불가 사진은 버리지 않고 별도 조건으로 평가한다.

| 지표 | 정의와 분모 | 용도 | 현 상태 |
| --- | --- | --- | --- |
| 캡션 사실 재현율 | 캡션에 보존된 사진의 필수 사실 수 / 라벨링한 필수 사실 수 | 내용 누락 감시 | 사람 판정 필요. 현재 `required_fact_recall`은 문자열 포함 진단 |
| 근거 없는 주장 사례율 | 사진에서 확인할 수 없는 기기·상태·원인을 **단정한** 캡션 수 / 검토한 캡션 수 | 핵심 안전 지표 | 사람 판정 필요. `forbidden_phrase_rate`로 대체 불가 |
| 정상 사진 오경보율 | gold에 가시적 이상이 없는데 있다고 단정한 수 / 정상 사진 수 | 과장 감시 | 실사진 음성셋과 사람 판정 필요 |
| OCR CER | 글자가 있는 사진의 전체 문자 편집 거리 / 정답 문자 수. 대소문자·공백 정규화 규칙 고정 | 전체 전사 오류 | `vlm.ocr_cer` 구현 |
| 핵심 토큰 F1 | OCR에 낸 오류코드·수치의 TP·FP·FN으로 계산한 micro-F1. 요약의 토큰은 제외 | 접수에 중요한 글자 | `key_token_f1`과 TP·FP·FN 구현. 숫자 포함 토큰과 오류 표시 뒤의 영문 코드를 오검출 후보로 센다. 단독 영문 코드의 오검출은 현재 포착하지 못하므로 실사진 라벨에 맞춰 추출 규칙 검수 필요 |
| 무문자 오검출률 | gold OCR이 `null`인데 비어 있지 않은 OCR을 낸 수 / 무문자 사진 수 | 허위 텍스트 감시 | `vlm.no_text_false_positive_rate` 구현 |
| 응답 계약 성공률 | JSON 파싱과 이미지 수·순서가 모두 맞는 요청 수 / 전체 요청 수 | 운영 안정성 | 단일 이미지 수는 구현. 파싱 실패는 실행 오류, 다중 이미지 순서는 미측정 |

실사진은 기기·설비 종류, 이상/정상, 글자 크기·흐림·반사, 글자 없음, 여러 장 입력으로 나눠 사례 수와 점수를 함께 보고한다. OCR 판독 불가 영역은 정답에서 명시하고 CER 분모에서 제외한다. 캡션의 근거 없는 주장과 증상 충실성은 먼저 사람 간 판정 기준을 맞춘 뒤 자동 판정기를 도입한다.

### 4. 민원 대화 운영·의도 라우팅

대화 운영은 `handle_complaint`가 병합한 초안·누락 슬롯·사용자 답변을 평가한다. **현재 실행은 이전 정답 초안**을 넣으므로 누적 모델 오류를 반영하지 않는다. 라우팅은 수집 중 그래프가 분류기를 우회하는 요청과 실제 `classify_intent` 호출 요청을 분리한다.

| 지표 | 정의와 분모 | 현 상태 |
| --- | --- | --- |
| 다음 누락 슬롯 계산 일치율 | 정답의 다음 누락 슬롯과 예측 `missing_fields[0]`이 일치한 턴 / 후속 질문이 필요한 턴 | `next_missing_slot_accuracy` 구현. 실행기가 `asked_field=missing_fields[0]`을 복사하므로 **실제 답변의 질문 품질 점수가 아니다** |
| 실제 후속 질문 슬롯 정확도 | 답변이 의미상 요청한 슬롯이 정답 다음 누락 슬롯과 일치한 턴 / 후속 질문이 필요한 턴 | 사람 판정 또는 검증된 판정기 필요. 현재 미구현 |
| 중복 질문률 | 이미 확인된 슬롯을 다시 요구한 후속 질문 턴 / 후속 질문 턴 | 의미 판정 미구현 |
| 한 턴 한 질문 준수율 | 한 가지 정보만 요구한 후속 질문 턴 / 후속 질문 턴 | 의미 판정 미구현 |
| 완료 턴 정확도 | 최초 `missing_fields=[]` 턴이 정답과 같은 대화 / 평가 대화 | `completion_turn_accuracy` 구현, 정답 초안 문맥 한정 |
| 경로 macro-F1 | 실제 분류기가 호출된 요청에서 `complaint`·`knowledge`·`clarify` 고정 라벨의 F1 평균 | `routing.macro_f1` 구현 |
| 민원↔지식 오분류율 | 두 경로 중 하나가 정답인 분류기 호출에서 서로 반대로 예측한 요청 / 해당 요청 | `fatal_cross_route_rate` 구현. `clarify` 정답 사례는 분모에서 제외 |
| 진입 노드 정확도 | 상태에 따른 실제 진입 노드가 정답과 일치한 요청 / 전체 라우팅 요청 | `routing.entry_accuracy` 구현 |

자유서술 판정 초안은 [JUDGE-PROMPTS.md](JUDGE-PROMPTS.md)를 사용한다. 자동 점수로 채택하기 전에는 모델 출력 없이 만든 사람 라벨로 판정기 일치도를 확인하고, 불일치 사례를 공개한다. 분류·OCR·라우팅의 정답 비교에 LLM 판정기를 쓰지 않는다.

### 합격선 결정 순서

1. 정답 라벨을 사람 검수하고, 애매한 경계 사례는 판정 규칙을 문서화한다.
2. 동일한 holdout에서 현재 모델을 측정하고 오류 유형·분모·반복 실행 변동을 확인한다.
3. 중요한 실패(없는 사실의 단정, 오류코드 오독, 원시 유형 혼동)에 허용할 최대 건수를 정한 뒤 비율 합격선으로 환산한다. 작은 셋에서 `0.95` 같은 비율만 단독으로 쓰지 않는다.
4. 이후 모델·프롬프트 변경은 같은 정답셋과 채점기 버전으로 baseline 대비 비교한다. 정답이나 채점 규칙을 바꾸면 기존 결과도 다시 채점한다.

## 1. Classification — issue_type

10종 택소노미 + `null`(이번 턴에 단서 없음) = **11클래스**로 취급한다.

### 1.1 평가 단위

두 단위를 모두 잰다. 하나만 재면 중간에 틀렸다 나중에 고쳐진 케이스가 보이지 않는다.

| 단위 | 재는 것 |
| --- | --- |
| 턴 | 그 턴에서 추출한 issue_type |
| 대화 최종 | 접수 시점 draft의 issue_type |

### 1.2 지표

| ID | 지표 | 계산 | 등급 | 게이트 |
| --- | --- | --- | --- | --- |
| C1 | **macro-F1** | `sklearn.metrics.f1_score(average="macro")` | 주 | ≥ 0.80 |
| C2 | **혼동 블록 recall** | `water_supply`·`drain`·`leak` 3클래스만 추린 recall | 주 | ≥ 0.75 |
| C3 | **null 오채움률** | gold가 `null`인데 값을 채운 비율 | 주 | ≤ 0.05 |
| C4 | per-class P/R/F1 | `classification_report` | 보조 | — |
| C5 | 혼동행렬 11×11 | `confusion_matrix` | 보조 | — |
| C6 | **MCC** | `matthews_corrcoef` | 보조 | ≥ 0.75 |
| C7 | flip rate | 3회 실행 중 답이 바뀐 비율 | 보조 | — |
| C8 | accuracy | — | 참고 | — |
| C9 | Cohen's κ | `cohen_kappa_score` | 참고 | — |

### 1.3 왜 macro-F1이 주지표인가

`noise`·`mold`·`pest`는 데이터가 적고 `leak`·`facility`는 많다. accuracy는 다수 클래스만 맞혀도 높게 나와 소수 클래스 실패를 숨긴다. 11클래스에서 accuracy와 Cohen's κ는 참고로만 싣는다.

### 1.4 C2를 따로 빼는 이유

프롬프트가 물 관련 3종에 구분 규칙을 명시해뒀다(`prompts.py` Disambiguation). 전체 macro-F1은 이 규칙이 무너져도 다른 7클래스가 받쳐줘서 안 떨어진다. 규칙의 효과는 그 3클래스만 잘라서 봐야 보인다.

### 1.5 측정 전제

**`other` 강제 주입을 분리해야 측정이 성립한다.** `node.py`는 필수 필드가 차면 issue_type이 `null`일 때 무조건 `other`로 채운다. 이걸 그대로 채점하면 진짜 분류 실패와 규칙에 의한 주입이 섞여 C1이 무의미해진다.

→ 강제 주입 여부를 플래그로 남기고, 주입된 턴은 C1~C3 집계에서 제외한다.

## 2. AI Extraction — complaint draft

`ComplaintDraft`는 belief state, `missing_fields`는 slot request다. 구조가 DST와 같으므로 MultiWOZ 계열 지표를 쓴다.

### 2.1 정답은 누적이 아니라 증분으로 적는다

`_merge_complaint_draft`가 이전 값을 덮어주기 때문에, 정답을 누적 draft로 적으면 **매 턴 전체를 재출력하는 모델도 만점**을 받는다. 프롬프트의 핵심 계약("현재 턴에 명시된 것만 추출")을 재려면 정답이 턴별 delta여야 한다.

각 슬롯에 `origin: current | history` 라벨을 필수로 붙인다. 이 라벨이 없으면 과추출을 측정할 수 없다.

### 2.2 슬롯별 채점 함수

슬롯 성격이 달라 비교 방식이 다르다.

| 슬롯 | 성격 | 채점 함수 |
| --- | --- | --- |
| `issue_type` | categorical | 버킷 1에서 처리 |
| `occurred_at` | categorical에 준함 | 날짜만 exact match (시각 무시) |
| `location` | non-categorical (span) | 정규화 후 exact match |
| `symptom` | non-categorical (자유서술) | 3단 채점 (2.4) |

`location` 정규화 = 공백 제거 + **동의어셋 파일** 치환(화장실=욕실=화장실겸욕실, 주방=부엌). 동의어셋이 없으면 정답이 표기 운에 좌우된다.

### 2.3 지표 — 추출 정확도

| ID | 지표 | 계산 | 등급 | 게이트 |
| --- | --- | --- | --- | --- |
| E1 | **대화 최종 JGA** | 종료 시점 draft의 4슬롯이 전부 정답인 대화 비율 | 주 | ≥ 0.85 |
| E2 | **턴 JGA** | 그 턴 delta의 4슬롯이 전부 정답인 턴 비율 | 주 | ≥ 0.70 |
| E3 | **과추출률** | `origin: history`인 슬롯을 채운 비율 | 주 | ≤ 0.05 |
| E4 | **location 정규화 EM** | 2.2의 정규화 후 일치율 | 주 | ≥ 0.90 |
| E5 | **`"모름"` 정밀도 / 재현율** | 거부 발화에만 `"모름"`이 떴는가 | 주 | P ≥ 0.95 / R ≥ 0.90 |
| E6 | **occurred_at 날짜 EM** | 전체 | 주 | ≥ 0.85 |
| E7 | **상대표현 슬라이스 EM** | 어제·3일 전·지난주만 추린 EM | 주 | ≥ 0.80 |
| E8 | 슬롯별 P/R/F1 | 슬롯 4개 개별 | 보조 | — |
| E9 | **AGA** | 값이 채워진 슬롯만 대상으로 한 정확도 | 보조 | — |
| E10 | **RSA** | 빈 슬롯 페널티를 완화한 JGA (Kim et al. 2022) | 보조 | — |
| E11 | 역행률 | 채워진 값이 명시적 정정 없이 null·오답으로 덮인 비율 | 주 | 0 |
| E12 | flip rate | — | 보조 | — |

E1이 E2보다 게이트가 높은 이유: 턴 단위는 한 번 틀려도 이후 턴에서 회복될 수 있지만, 최종 draft는 그대로 관리자에게 간다. 제품 품질은 E1이다.

### 2.4 `symptom` 3단 채점

자유서술이라 하나의 함수로 못 잰다. 자동 지표는 환각을 못 잡고, judge만 쓰면 재현이 안 된다.

| 단 | 지표 | 내용 | 등급 | 게이트 |
| --- | --- | --- | --- | --- |
| ① 하드룰 | E13 | `"모름"`·플레이스홀더 출력 시 무조건 0점 | 주 | 위반 0건 |
| ② 자동 | E14 | gold symptom의 핵심 내용어(명사·용언 어간) 재현율 | 주 | 평균 ≥ 0.60 |
| ③ 판정 | E15 | judge 이진 — **충실성**(턴·히스토리·사진에 없는 사실을 넣지 않음) | 주 | ≥ 0.95 |
| ③ 판정 | E16 | judge 이진 — **충분성**(이 문장만으로 관리자가 출동 가능) | 주 | ≥ 0.85 |

②는 회귀 감시용(싸고 재현됨), ③은 품질 판정용. ①은 `symptom`에 placeholder가 들어가면 민원 자체가 처리 불가라 예외 없다.

**judge 검증이 먼저다.** E15·E16을 쓰기 전에 인간 라벨 50건과의 **Cohen's κ ≥ 0.6**을 확인하고 리포트에 같이 싣는다. 이걸 안 하면 judge 점수는 근거가 없다.

### 2.5 지표 — 수집 대화 진행

추출이 맞아도 대화가 길어지면 제품이 실패한다. 수집 규칙 준수를 따로 잰다.

| ID | 지표 | 계산 | 등급 | 게이트 |
| --- | --- | --- | --- | --- |
| D1 | **중복 질문율** | draft에 이미 있는 슬롯을 다시 물은 비율 | 주 | 0 |
| D2 | **한 턴 한 질문 준수율** | 후속 질문이 슬롯 하나만 묻는 비율 | 주 | ≥ 0.95 |
| D3 | **질문 순서 준수율** | `location` → `symptom` 순서 | 주 | ≥ 0.95 |
| D4 | **완성 턴 수** | `missing_fields`가 빌 때까지의 턴 수, median·p90 | 주 | median ≤ 이론 최소 + 1 |
| D5 | reply_source 분포 | `llm` / `fixed` / `complete` 비율 | 보조 | — |

D5는 이미 `node.py`가 로그로 남기고 있다. `fixed` 비율이 높다는 건 LLM이 낸 `missing`·`reply`가 규칙과 어긋나 고정 문구로 떨어진다는 뜻이므로, 운영 중에 공짜로 얻는 조기 경보다.

## 3. VLM Analysis — 캡셔닝 + OCR

`summary`와 `ocr_text`는 태스크가 달라 지표를 섞지 않는다.

### 3.1 캡셔닝 표준 지표를 그대로 쓰지 않는 이유

| 지표 | 배제 이유 |
| --- | --- |
| BLEU | 단어 n-gram 정밀도. 교착어라 어미만 바뀌어도 점수가 무너진다. 한국어 토크나이저 선택에 결과가 종속됨 |
| METEOR | WordNet 동의어 매칭 의존 → 영어 전용 |
| CIDEr | 이미지당 참조 캡션 5개(MS-COCO) 기준으로 캘리브레이션된 코퍼스 TF-IDF 지표. 참조 1개·30장 규모에서는 IDF 항이 노이즈 |
| SPICE | 캡션을 scene graph로 파싱 — 영어 의존구문 분석기 전용 |
| CLIPScore | reference-free라 매력적이지만 한국어 CLIP 품질이 받쳐주지 않는다. 보류 |

대체: 표층 유사도는 **chrF++**(문자 n-gram F-score, 토크나이저 불필요)를 보조로만 쓰고, 주지표는 **사실 슬롯 채점**과 **환각률**로 세운다. 제품이 요구하는 것은 "얼마나 비슷하게 썼나"가 아니라 "사실을 빠뜨리지 않고 없는 것을 만들지 않았나"다.

### 3.2 정답 형태

```json
{"photo": "p07.jpg", "device": "보일러", "anomaly": true,
 "key_tokens": ["E4", "88"],
 "forbidden": ["누수", "곰팡이", "균열"],
 "refs": ["보일러 조작부에 E4 에러가 떠 있고 온도는 88도로 표시된다"],
 "gold_ocr": "E4  88℃  운전"}
```

- `forbidden` — 이 이미지에 대해 나오면 환각으로 세는 표현. 환각을 자동 판정하는 유일한 수단이다.
- `refs` — 전체 30장 중 **10장만** 3개씩 작성한다. 30장 규모에서 표층 지표를 주지표로 세우는 것은 통계적으로 성립하지 않으므로, chrF++는 모델 교체 시 문체가 뒤집혔는지 보는 추세 감시용으로만 둔다.
- **음성셋 8장** — 정상 기기·무관 사진(스크린샷 등). `anomaly: false`, `device`는 보이는 그대로. 음성셋이 없으면 "모든 사진에 문제가 있다"고 답하는 모델이 만점을 받는다.

### 3.3 지표 — summary (캡셔닝)

| ID | 지표 | 계산 | 등급 | 게이트 |
| --- | --- | --- | --- | --- |
| V1 | **사실 재현율** | `device` 일치 ∧ `anomaly` 일치 ∧ `key_tokens` 재현율의 이미지별 점수 평균 | 주 | ≥ 0.80 |
| V1a | device 정확도 | 동의어셋 적용 후 일치율 | 보조 | — |
| V1b | anomaly 정확도 | 이상 유무 이진 정확도 | 보조 | — |
| V1c | key_token 재현율 | 필수 토큰 포함율 | 보조 | — |
| V2 | **CHAIR_s** | 환각을 하나라도 포함한 캡션 비율 (Rohrbach et al. 2018) | 주 | ≤ 0.05 |
| V3 | **CHAIR_i** | 환각 언급 수 / 전체 언급 수 | 주 | ≤ 0.03 |
| V4 | **오경보율** | 음성셋 8장에서 `anomaly: true`로 판정한 비율 | 주 | ≤ 0.10 |
