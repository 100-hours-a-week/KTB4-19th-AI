# AI 기능 평가 체계와 구축 순서

**현재 담당 범위:** 민원 `issue_type` 분류, `complaint_draft` 추출, 민원 대화 운영, 의도 라우팅, VLM 캡셔닝·OCR. RAG는 별도 담당 범위로 아래 표에 현황만 남긴다.

## 목적

각 AI 기능에 대해 **평가지표 → 지표에 필요한 골든 셋 → 모델 실행 → 채점 → 오류 분석**을 한 묶음으로 만든다. 이 문서는 무엇을 평가하고 어떤 순서로 구축할지 정한다. 현재 점수나 출시 합격선을 선언하지 않는다.

골든 셋은 정답 문장만 모은 파일이 아니다. 지표 계산에 필요한 유형, 근거 문서, 슬롯 값, 사진에서 보이는 사실, 읽히는 문자와 같은 정답 라벨을 포함한다. 출력이 달라질 수 있는 AI 판단은 평가하고, 스키마·상태 전이 같은 결정적 동작은 단위 테스트로 검증한다.

## 태스크별 지표와 골든 셋

| 평가 대상 | 먼저 계산할 지표 | 골든 셋에 필요한 정답 | 함께 확인할 실패 |
| --- | --- | --- | --- |
| **RAG 검색·답변** | 정답 문서 Recall@k, 답변의 근거 충실성, 질문 해결률, 답 없음 판정 정확도 | 질문, 건물·구역, 답변 가능 여부, 근거 문서, 답에 필요한 핵심 사실 | 다른 건물 문서 혼입, 근거 없는 금액·날짜·연락처, 답이 있는데 회피하거나 답이 없는데 생성 |
| **`issue_type` 분류** | 원시 11클래스 macro-F1, 클래스별 재현율, 급수·배수·누수 구분 정확도, `null` 오채움률 | 현재 발화와 필요한 문맥, 유형 또는 `null`, 판단 근거가 된 표현 | 비슷한 유형 간 혼동, 정보가 없는데 유형을 생성, 병합 후 `other` 보정값을 원시 예측으로 오인 |
| **`complaint_draft` 추출** | 슬롯별 정확도, 현재 턴 `delta` 전부 일치율, 기존 값 재추출률, 최종 초안 성공률 | 이전 초안·대화, 턴별 `delta`, 슬롯 출처, 최종 초안, 증상의 필수 사실 | 명시적 정정 무시, 과추출, 증상에 없는 사실 추가, 필수 정보 누락 |
| **VLM 캡셔닝·OCR** | 캡션 사실 재현율, 근거 없는 주장 사례율, OCR CER, 핵심 코드·수치 F1 | 실사진, 확인 가능한 사실, 정상·이상 라벨, 문자 전사, 핵심 토큰, 촬영 조건 | 보이지 않는 고장 원인 단정, 정상 사진 오경보, 글자 없는 사진의 OCR 생성, 흐림·반사에서 오독 |
| **의도 라우팅** | 경로 macro-F1, 민원↔지식 치명 오분류율 | 발화, 이전 경로·수집 상태, 정답 경로와 진입 노드 | 민원 대화를 지식 답변으로 전환, 모호한 후속 발화의 경로 이탈 |

RAG에서 검색 결과 전체의 정밀도를 계산하려면 **관련된 문서 전체**가 라벨링되어 있어야 한다. 현재처럼 대표 근거 문서 하나만 있으면 먼저 그 문서의 Recall@k를 측정하고, 전체 관련성 라벨을 마련한 뒤 context precision을 추가한다. 답변 충실성과 질문 해결률은 서로 다르므로 각각 판정한다.

분류는 병합 전 `delta.issue_type`을 채점한다. 추출은 턴별 `delta`와 누적 `draft`를 분리한다. 캡션과 OCR도 분리해 OCR 핵심 토큰은 `ocr_text`에서만 채점한다. 자유 문장의 단어 포함률은 진단용이며 증상 충실성이나 사진 환각 판정을 대신하지 않는다.

### 1단계 산출물: 채점 계약

| 태스크 | 계산 단위와 분모 | 자동 채점과 사람 판정의 경계 |
| --- | --- | --- |
| RAG 검색 | 답변 가능한 질문 중 지정 근거 문서가 top-k에 있는 비율. 검색 게이트에서 차단되면 실패 | 문서 식별자 매핑을 먼저 고정한다. 다른 관련 문서 전체를 라벨링하기 전에는 context precision을 계산하지 않는다 |
| RAG 답변 | 답변 가능 여부의 정밀도·재현율 및 답변의 필수 사실 보존·근거 없는 주장 | `has_sufficient_evidence`는 자동 채점. 자유 답변의 사실 보존·근거 충실성은 사람 판정을 기준으로 한다 |
| 유형 분류 | 10개 유형과 `null`을 고정한 11클래스 macro-F1. `null` 오채움률은 gold `null` 턴 중 유형을 낸 비율 | 최종 초안에 자동 주입된 `other`를 원시 분류 예측에 섞지 않는다 |
| 초안 추출 | 턴별 4슬롯 `delta` 일치율·슬롯별 정확도. 최종 성공률은 평가 대화 중 접수 가능한 최종 초안의 비율 | 증상 문장의 필수 사실 누락·근거 없는 추가는 사람 판정. 이전 정답 초안을 넣은 점수와 이전 모델 초안을 넣은 점수를 따로 보고한다 |
| VLM 캡션 | 라벨링한 필수 사실 중 보존된 사실 비율과 평가 캡션 중 근거 없는 단정이 있는 캡션 비율 | 단어 포함이나 금지어 검색은 진단용. 사진을 본 사람의 사실 판정을 기준으로 한다 |
| VLM OCR | 글자가 있는 사진의 전체 편집 거리 / 정답 문자 수(CER). 핵심 토큰은 OCR에서의 TP·FP·FN으로 F1 계산 | 판독 불가 영역은 모델 실행 전에 표시한다. 글자 없는 사진의 OCR 오검출률은 별도 집계한다 |
| 의도 라우팅 | 실제 분류기가 호출된 요청의 route macro-F1과 민원↔지식 오분류율 | 수집 상태에서 분류기를 우회한 요청은 진입 노드 계약으로 따로 검사한다 |

모델 오류·누락은 성공 사례만 골라 분모를 줄이지 않고 **실행 성공률과 실패 ID**로 보고한다. 비율은 분자·분모를 함께 출력하고 분모가 0이면 `null`로 둔다. 합격선은 실제 holdout 검수와 오류 비용 판단 뒤 별도로 기록한다.

## 골든 셋을 신뢰할 수 있게 만드는 규칙

1. **개발 셋과 최종 평가 셋을 분리한다.** 기존 합성 사례는 기능 커버리지·회귀 점검의 출발점으로 사용한다. 실제 사례의 최종 평가 셋은 프롬프트 수정에 쓰지 않고 고정한다. 같은 민원·문서·사진의 변형은 두 셋에 나눠 넣지 않는다.
2. **모델 출력 없이 정답을 작성한다.** 유형 경계, 답변 가능 여부, 사진만으로 알 수 없는 원인처럼 애매한 항목에는 판정 규칙과 근거를 남긴다. 자유 서술의 사실성은 독립 검수 후 의견 불일치를 정리한다.
3. **대표 사례와 어려운 사례를 구분해 보고한다.** 실제 유입 분포와 물 관련 유형 혼동·정정 발화·정상 사진·흐린 오류코드 같은 도전 사례를 하나의 평균으로 숨기지 않는다. 모든 비율에는 분모와 오답 사례를 함께 남긴다.
4. **실행 실패를 누락하지 않는다.** 모델 호출·파싱 실패, 누락 예측, 다중 이미지 수·순서 오류는 성공 점수의 분모에서 조용히 제거하지 않고 별도로 기록한다.
5. **합격선은 오답 비용과 표본 수를 보고 정한다.** 현재 모델 점수나 임의의 `0.80`을 합격선으로 삼지 않는다. 먼저 허용 가능한 중요한 실패의 건수를 정하고, 검수된 평가 셋의 사례 수·불확실성과 함께 판정한다. 이전 실행 대비 변화폭은 절대 품질 기준과 구분한다.

### 2단계 RAG 구조 검수 결과

합성 RAG 235문항은 답변 가능 135건과 불가능 100건이다. 지정 출처 1개만 가진 정답이므로 검색 지표의 이름은 **지정 출처 Hit@k**로 둔다. 전체 관련 문서 Recall·precision은 아직 측정할 수 없다. 질문 문구가 여러 건물에 반복되는 27개 계열은 건물 격리 검사에 유용하지만 개발 셋과 최종 셋을 나눌 때 같은 계열을 함께 묶어야 한다.

구조 검수에서 누락된 `zone_id` 42건, 문서·정답의 날짜 요일 3건, 주차면 수 표현 1건을 수정했다. 원본에서 생성하는 PDF도 다시 만들고 검사했다. `validate.py --gold`는 ID·건물·구역·인용 문서 버전·QA 카드 연결을 검사한다. 이는 **구조 검수** 결과이며 답변 문장 전체에 대한 독립적인 도메인 검수 완료를 뜻하지 않는다.

RAG 평가는 **2026-09-29 기준, 관리자 QA 카드 재색인 전**으로 고정한다. 현재 답변 불가 100건 중 50건에는 관리자 답변 카드가 있어 재색인 후에는 정답 상태가 바뀐다. 스캔·사진·PII·정제 경계 문서를 인용하는 답변 가능 사례 10건도 있다. 현재 제품 코드는 OCR과 마스킹 후 색인을 시도하므로, 오래된 데이터 설명의 ‘색인 제외’ 가정을 그대로 적용하지 않고 실제 색인 결과와 실패 사유를 기록한다. `b002-q25`의 야간 방문 주차는 문서에 최대 4시간 규정이 있어 ‘답변 불가’가 맞는지 도메인 검수가 남아 있다.

## 구축 순서

| 순서 | 작업 | 완료 기준 |
| --- | --- | --- |
| **1. 지표 계약** | 태스크별 평가 단위·계산식·정답 필드·오류 처리·사람 판정 항목을 확정 | 서로 다른 사람이 같은 사례를 같은 기준으로 채점할 수 있는 라벨링 규칙 |
| **2. 기존 골든 셋 검수** | RAG·민원·라우팅 합성 정답의 경계와 중복을 점검하고 개발용/최종 판정용을 분리 | 각 사례의 정답·근거·버전·검수 상태 확인 가능 |
| **3. 골든 셋 보강** | 실제 민원 표현과 질문을 추가하고, 확보된 실사진에 보이는 사실·OCR·촬영 조건을 라벨링 | 대표 사례와 중요한 실패 사례가 모두 포함됨 |
| **4. 실행·채점 연결** | 태스크별 `run.py`가 원본 예측과 모델·프롬프트·데이터 버전을 저장하고 `score.py`가 저장 예측만 채점 | 정상 예측과 누락·오류 예측에 대한 재현 가능한 결과 |
| **5. 전체 흐름 검증** | 검색→답변, 라우팅→민원 접수, 이전 **모델** 초안을 이어 넣는 대화를 평가 | 구성 요소 점수와 실제 작업 성공률을 함께 보고 |
| **6. baseline·판정** | 검수된 평가 셋으로 현재 모델을 측정하고 조건별 오답을 분석해 합격선을 고정 | 품질 기준과 회귀 기준이 구분된 비교 보고서 |

**현재 담당 실행 우선순위:** 민원 분류·추출 → 대화 운영·의도 라우팅 → 이미지 라벨 검수 후 VLM. RAG는 별도 담당이 진행한다. VLM의 지표·라벨 양식은 먼저 만들고, 실제 품질 측정은 이미지 확보 후 진행한다. 모든 단계에서 골든 셋 버전과 채점기 버전을 함께 보존한다.

## 실사진 확보 기준

현재 VLM은 이미지 유형을 직접 분류해 반환하지 않고 **캡션(`summary`)과 OCR(`ocr_text`)**을 반환한다. 아래 장수는 이 두 출력의 평가 기준이다. 별도의 다중 클래스 이미지 분류 모델을 평가하려면 클래스별 표본 수를 다시 설계해야 한다.

향후 사진만 입력받아 `issue_type`을 분류한다면, 파일럿과 별도로 **평가 대상 클래스당 최소 30장**을 확보한다. 텍스트 분류의 10개 유형을 그대로 적용하면 300장에 정상·유형 불명 등 거절 사례를 별도로 더해야 한다. 사진에서만 유형을 판별할 수 없는 사례는 억지로 10개 유형 중 하나로 라벨링하지 않는다. 클래스별 오류율 5% 미만을 관측 오류 0건으로 주장하려면 해당 클래스에 약 60장 이상이 필요하다. 클래스 정의와 실제 모델 출력이 정해지면 이 수량을 다시 확정한다.

- **파일럿 20~30장:** 라벨링 규칙과 판독 불가 기준을 맞추는 개발용. 최종 점수에 섞지 않는다.
- **최종 평가용 최소 120장:** 정상/이상 × 글자 있음/없음의 네 칸을 각각 약 30장으로 시작한다. 따라서 정상 사진 최소 60장, 글자가 있는 사진 최소 60장을 확보한다. 같은 사진의 크롭·연속 촬영본은 중복 사례로 센다.
- **다중 이미지 요청 10건 이상:** 확보한 서로 다른 사진 2~3장을 묶어 입력 순서와 개수 계약을 확인한다. 이는 사진 장수와 별도의 요청 수다.
- 각 사진에는 기기·설비, 눈에 보이는 상태, 텍스트의 정확한 전사, 오류코드·수치, 정상/이상, 흐림·반사·작은 글자 여부를 기록한다. 사진만으로 알 수 없는 고장 원인은 정답으로 쓰지 않는다. 개인정보를 가릴 때 평가할 문자까지 지우지 않는다.

120장은 **평가 시작 규모**이지 모든 비율의 정밀도를 보장하는 수가 아니다. 예를 들어 정상 사진 60장에서 오경보가 0건이면 실제 오경보율의 단측 95% 상한은 `1 - 0.05^(1/60) ≈ 4.9%`다. 30장에 0건이면 약 9.5%이므로 5% 미만이라고 주장할 수 없다. 관측 오류가 나오거나 설비별 성능을 따로 주장하려면 사진을 더 모아야 한다.
