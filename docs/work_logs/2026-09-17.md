## 작업 내용

- 완료:
  - `clarify` route의 첫 응답은 고정 질문으로 처리한다.
  - 이전 `current_route`도 `clarify`이고 이번 분류도 `clarify`인 경우에만 LLM이 대화 이력 기반 재질문을 생성한다.
  - generic Agent의 route와 민원 feature 내부 `ComplaintState`를 분리했다. clarify 분기는 민원 상태를 변경하지 않는다.
  - intent 프롬프트에서 `current_route=clarify`는 route 유지 편향 없이 현재 발화와 이력으로 다시 분류하도록 수정했다.
  - 대화 API를 `POST /api/v3/ai/converse`로 연결하고, graph 결과를 공통 응답 계약으로 변환했다.
  - 민원에만 속하는 상태 이름을 `ComplaintState`/`complaint_state`/`next_complaint_state`로 구체화했다.
  - Wiki v18 계약에 맞춰 요청의 `user_action`을 제거하고, 성공 응답의 `trace_id`를 최상위 필드로 이동했다.
  - 실제 clarify graph를 타는 API E2E 테스트와 `400`/`422` 공통 오류 응답을 추가했다.
- 진행 중:
  - 실제 LLM 스모크 실행은 API 키 설정 수정 후 재확인한다.
